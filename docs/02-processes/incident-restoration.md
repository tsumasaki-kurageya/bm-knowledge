# 応急対応・復旧を進め、利用再開を確認する

被害が広がらないように応急対応を調整し、復旧後に建物・設備を再び使えるか確認します。

## このページで扱う範囲

官庁施設向け保全委託における非常時の連絡・応急支援・復旧調整を具体例とする。機器の安全操作、消防・救助の専門手順を記載するものではない。利用再開の最終判断は、参照資料だけでは共通化できない。

手順は資料をもとに読みやすく整理したものです。資料に書かれた内容と、確認が必要な点を根拠欄で区別しています。

## いつ始めるか

危険・障害への対応決定、応急後の復旧、修理完了の連絡。

変更や異常の発生から直接始まることもあり、前の業務の完了だけが開始条件ではありません。

## 法令・契約・日常管理との関係

- 法令：事象・設備による義務や権限を確認。
- 契約：応急支援・費用等の条件。
- 運用：安全確保と復旧の連絡調整。

一つの仕事に、法令・契約・日常管理の条件が重なることがあります。具体的な義務者・周期・資格・権限は建物・設備・契約の条件から確認する。

## どこまでできれば完了か

当面の対応結果、再開可否の判断状況、残る制約と恒久対策への引渡しを記録できることを本書の終了判定とする。仮復旧・制限付き運用・再開未決を完全復旧と扱わない。再開条件が確認できない場合は未決として扱う。

## 関係者・役割

担当者の例を示します。一人が複数の役割を持つ場合も、分担する場合もあります。責任や承認できる範囲は、法令・契約・建物の管理ルールで確認します。

| 担当者の例 | 役割 | 責任・判断 |
| --- | --- | --- |
| 管理者・権限者 | 対応・再開の判断 | 使用制限・再開等の判断 |
| 専門業者・関係機関 | 専門対応 | 専門対応 |
| 利用者・運用担当者 | 影響確認・情報共有 | 影響確認と情報共有 |

## 必要な情報

- 異常情報
- 連絡体制・権限
- 専門家の判断
- 復旧結果

## 標準フロー

F番号は[詳細フローの根拠](#詳細フローの根拠)の参照資料。情報確認・連絡・記録は並行し得るため、表の全項目が揃うまで次の対応を止める順序とはしない。未確認とした手続は、実施ルールの追加ではなく確認事項である。

| 手順・担当 | 行うこと | 得られる情報・根拠 |
| --- | --- | --- |
| R1 事象と対応条件を確認（管理者・対応責任者） | 入手した異常情報と、事前の体制・対応条件を確認する。 | 対応に使う情報と権限の不明点。根拠・未確認：F1第1編1.1.7、第3編1.1.12〜13 |
| R2 必要な応急対応を調整（管理者・専門対応者） | 危険と権限に応じた対応・連絡を行う。 | 当面の措置と影響。根拠・未確認：F1第1編1.1.7、第2編1.1.7。個別操作は対象外 |
| R3 復旧・恒久対策を手配（管理者・技術者） | 早期復旧の対応条件に沿い、必要な工事検討を[修繕案の具体化（PROCESS-017）](repair-design.md)へ渡す。 | 復旧に必要な対策・調整事項。根拠・未確認：F1第3編1.1.12／発注権限・恒久対策の内容は未確認 |
| R4 結果と再開条件を確認（専門的確認者・再開判断者） | 修理等の結果と残る制約を、利用再開の判断へ渡す。 | 再開判断の結果または未決事項。根拠・未確認：判断に必要な情報と引継ぎについての整理案／統一の試験基準・決裁者は未確認 |
| R5 残課題・備えへ引き継ぐ（管理者・記録担当者） | 経過を記録し、恒久対策と事前の備えに残る課題を引き渡す。 | 対応履歴・未完了事項。根拠・未確認：F1第1編1.2.4／備えの見直しは[非常時の備え（PROCESS-020）](emergency-preparedness.md)への引継ぎ |

## 判断ポイント・分岐

| 判断すること | 分岐・扱い | 根拠または確認条件 |
| --- | --- | --- |
| 重大な危険が認められる | 必要な措置・連絡を扱う。計画予算の確定を全ての応急対応の先行条件にしない。 | F1第3編1.1.12〜13／具体的な権限と安全措置は個別確認 |
| 応急支援の範囲・費用が不明 | 実施状況と協議が必要な点を分ける。費用の自動承認・無制限な支出は定めない。 | F1第1編1.1.7(d)(e) |
| 工事完了の連絡が来た | 完了報告だけで再開可とせず、必要な確認結果・制約を判断者へ渡す。 | 利用再開の判断についての整理案／設備別の判定条件は未確認 |

## 分岐・例外

| 代表的な例外 | 扱い | 根拠または未確認 |
| --- | --- | --- |
| 仮復旧のみ実施できた | 残る制約と恒久対策を分けて記録する。 | 本書の終了判定の整理／許容条件・監視体制は未確認 |
| 再開を判断する者・試験条件が不明 | 未確認を記録し、再開の承認を推定しない。 | 未確認：設備・施設運営・契約上の権限 |
| 災害で受託業務の継続が困難 | 管理者への報告と支援条件の確認を扱う。 | F1第1編1.1.7(c)〜(e) |
| 復旧後に再発する | 以前の完了記録で新たな異常を相殺せず、影響を再評価する。 | 再発時の影響判断についての整理案／再発時の責任・費用は未確認 |

## 次の業務へ渡す情報と条件

渡す情報は、応急・復旧の経過、再開可否と制約、恒久対策・残課題です。次の関係は資料を組み合わせた整理案で、担当・権限・期限は建物ごとに確認します。

複数の担当へ並行して引き継ぐ場合があります。危険の連絡は、記録や報告書の完成を待たずに行います。

### 修繕・交換の方法と範囲を決める

[PROCESS-017：修繕・交換の方法と範囲を決める](repair-design.md)へ引き継ぐのは、工事候補を技術的に具体化するときです。技術者と費用負担者等が性能・案・費用を検討。未決なら調査・計画調整を行う。

[この業務の資料](#情報源)・[引継ぎ先の資料](repair-design.md#情報源)に基づく整理案。未確認：設計・許認可の要否、代替案の比較基準。小修繕で省略できる成果の範囲。

### 非常時の連絡・対応を決めて訓練する

[PROCESS-020：非常時の連絡・対応を決めて訓練する](emergency-preparedness.md)へ引き継ぐのは、連絡・役割・訓練計画の変更が必要なときです。管理者・防火防災担当者等が備えを確認。変更不要なら現行計画を維持する。

[この業務の資料](#情報源)・[引継ぎ先の資料](emergency-preparedness.md#情報源)に基づく整理案。未確認：法定の計画・訓練等の適用と担当。計画作成と訓練で異なる担当・成果。

### 台帳・図面・作業記録を更新し、引き継ぐ

[PROCESS-021：台帳・図面・作業記録を更新し、引き継ぐ](records-handover.md)へ引き継ぐのは、成果・判断・変更情報が発生または更新されたときです。記録管理者が対象・版・未完了事項を確認。欠落は不足として残す。

[この業務の資料](#情報源)・[引継ぎ先の資料](records-handover.md#情報源)に基づく整理案。未確認：保存年限・アクセス権・版管理。所有者変更時の図書引継ぎと欠落資料の扱い。

## 顧客の困りごとを確認する

以下は、この業務を理解するための質問です。顧客で確認済みの課題ではありません。

管理者・専門業者・再開判断者に、次の点を聞きます。

仮復旧、利用再開、恒久対策の状況を関係者で共有できていますか。再開判断で不足した情報はありますか。

確認に使う情報：復旧結果、利用制限、未完了の対策。工事完了と利用再開の判断を分ける。
