# 建物・設備を点検し、状態を判断する

建物や設備の傷み・不具合を調べ、手入れ・修理・追加調査が必要か判断します。

## このページで扱う範囲

このページの手順は、参照仕様の第2編にある定期・臨時点検の一般事項を対象とする。日常点検・各法定点検・機器別の詳細方法まで同じ手順に統一しない。日常点検は本業務の概略範囲に残し、個別の手順は追加調査する。

手順は資料をもとに読みやすく整理したものです。資料に書かれた内容と、確認が必要な点を根拠欄で区別しています。

## いつ始めるか

日常・定期の予定、災害・不具合後、作業後の状態確認の必要。

予定に沿って繰り返す場合も、条件の変更がなければ計画・発注・承認を毎回やり直すとは限りません。周期・期限は法令・契約・管理計画で確認します。

## 法令・契約・日常管理との関係

- 法令：該当する点検は適用・資格等を確認。
- 契約：任意点検も含む。
- 運用：日常・定期・臨時を属性として区別。

一つの仕事に、法令・契約・日常管理の条件が重なることがあります。具体的な義務者・周期・資格・権限は建物・設備・契約の条件から確認する。

## どこまでできれば完了か

対象に対する点検・評価結果と、対象外・未確認の範囲を区別し、必要な報告・措置への引渡しを確認できることを本書の終了判定とする。点検終了は不具合の解消や法定報告の完了を意味しない。実施できない部分を異常なしとして終了しない。

根拠のある作業・報告の範囲は標準フローの各行、具体的に決められない条件は判断・例外の表に示す。

## 関係者・役割

担当者の例を示します。一人が複数の役割を持つ場合も、分担する場合もあります。責任や承認できる範囲は、法令・契約・建物の管理ルールで確認します。

| 担当者の例 | 役割 | 責任・判断 |
| --- | --- | --- |
| 点検者・専門家 | 点検・技術評価 | 状態把握と技術評価 |
| 管理者 | 対応への引渡し | 対応への引渡し |
| 利用者・運用担当者 | 状態情報・実施条件の提供 | 状態情報と入室条件の提供 |

## 必要な情報

- 対象・履歴
- 図書
- 要求・判定基準
- 発生状況

## 標準フロー

参照資料は[詳細フローの根拠](#詳細フローの根拠)。各行の「根拠」はその資料の編・節を示す。以下は読解上の段階であり、相互の調整や確認を必ず一度ずつ直列に実行するとの規定ではない。

| 手順・担当 | 行うこと | 得られる情報・根拠 |
| --- | --- | --- |
| I1 対象・適用条件を確認（点検者・管理者） | 指定された対象と該当項目を確認する。法定点検等の条件を区別する。 | 対象・適用範囲。根拠・未確認：第2編1.1.2、1.2 |
| I2 既知の状態を確認（点検者・管理者） | 劣化・故障状況を聞き取り、点検に用いる。 | 事前の状態情報。根拠・未確認：第2編1.1.4(b) |
| I3 対象に合う方法で点検（点検者・必要な資格を持つ者） | 適用する作業内容と測定機器を確認して状態を調べる。 | 観測・測定結果。根拠・未確認：第2編1.1.4(a)(c)、1.2／対象別の方法は個別確認 |
| I4 異常時の確認・連絡（点検者・管理者） | 類似箇所の確認と、危険に応じた報告・措置を扱う。危険発見時は残りの点検より先に対応が必要となり得る。 | 異常・影響の連絡情報。根拠・未確認：第2編1.1.4(d)、1.1.7 |
| I5 措置の必要性を評価（点検者・専門的判断者） | 点検結果から保守等の必要性を判断する。 | 対応要否・判断根拠。根拠・未確認：第1編1.1.2の点検の定義、第2編1.1.4(a) |
| I6 結果を報告・引渡し（報告担当者・管理者） | 指定の対象について結果をまとめ、合意した様式・提出条件で報告する。 | 点検結果・未確認範囲・必要な対応。根拠・未確認：第2編1.1.2(b)、第1編1.4.7 |

## 判断ポイント・分岐

| 判断すること | 分岐・扱い | 根拠または確認が必要な条件 |
| --- | --- | --- |
| 点検項目の対象部分が存在しない | 該当する対象の有無を区別する。対象外と点検不能を混同しない。 | 第2編1.1.2(c) |
| 容易に点検できない箇所がある | 適用される省略条件を確認する。法定点検・特記には例外があるため、自動的に省略しない。 | 第2編1.1.8／個別適用・処理方法は未確認 |
| 異常を発見する | I4へ。類似箇所の確認と、危険に応じた速やかな報告・措置を扱う。 | 第2編1.1.4(d)、1.1.7 |
| 保守・修繕等の対応が必要 | I5の評価を次の対応担当へ渡す。評価だけで工事の承認を行ったとは扱わない。 | 第1編1.1.2、第2編1.1.4／費用・実施権限は未確認 |

## 分岐・例外

| 代表的な例外 | 扱い | 根拠または未確認事項 |
| --- | --- | --- |
| 対象外の箇所で異常を発見する | 依頼対象外という理由で情報を捨てず、管理者へ報告する。 | 第2編1.1.2(b) |
| 停止困難・立入困難で未確認になる | 確認できない範囲を区別する。法定・契約条件を確認し、代替確認を推測で決めない。 | 第2編1.1.8／代替方法・再点検条件は未確認 |
| 落下等の危険や使用継続の支障を発見する | 報告・危険防止等の対応を切り離さず扱う。具体的な現場作業は有資格者・権限者等の条件で判断する。 | 第2編1.1.7／個別の措置手順は範囲外 |
| 同じ対象・内容の点検が重複する | 参照仕様の重複に関する条件を確認する。別の法定検査まで一律に代替できるとは扱わない。 | 第2編1.1.8(b)／個別の法令・契約条件は未確認 |

## 使用される情報・帳票

判断や引継ぎに使う情報を示します。必要な書式・保存方法は契約や建物ごとの管理ルールで確認します。

| 情報・帳票 | 使用目的 | 根拠・適用条件 |
| --- | --- | --- |
| 対象一覧・仕様・適用する点検項目 | I1の対象と実施範囲を確認 | 第2編1.1.2 |
| 劣化・故障情報、既存図書 | I2〜I3の判断を支える | 第2編1.1.4(b)、第1編1.2.3 |
| 点検結果・報告書 | 状態と対応要否を報告する | 第1編1.4.7、第2編1.1.2 |
| 対象外・未確認範囲の情報 | 点検できた範囲を説明する | 結果として残す情報の整理案。専用帳票・記載様式は未確認 |

## 作業後に残すもの

- 点検・評価結果
- 対応要否・追加調査事項
- 確認できなかった範囲

## 次の業務へ渡す情報と条件

渡す情報は、点検・評価結果、対応要否・追加調査事項、確認できなかった範囲です。次の関係は資料を組み合わせた整理案で、担当・権限・期限は建物ごとに確認します。

複数の担当へ並行して引き継ぐ場合があります。危険の連絡は、記録や報告書の完成を待たずに行います。

### 契約どおりに作業されたか確認する

[PROCESS-008：契約どおりに作業されたか確認する](completion-check.md)へ引き継ぐのは、依頼に基づく実施結果を確認する時期になったときです。確認者が条件と成果を照合。不一致は是正へ、受領可否は権限者が判断する。

[この業務の資料](#情報源)・[引継ぎ先の資料](completion-check.md#情報源)に基づく整理案。未確認：検査・受領・支払の条件。部分完了や指摘付き受領の扱い。

### 将来の修繕と費用を計画する

[PROCESS-004：将来の修繕と費用を計画する](long-term-plan.md)へ引き継ぐのは、劣化・費用・方針が中長期の見通しに影響するときです。計画担当者が前提を見直し、権限者が資金方針を判断。計画は発注承認を兼ねない。

[この業務の資料](#情報源)・[引継ぎ先の資料](long-term-plan.md#情報源)に基づく整理案。未確認：計画期間・費用精度・見直し周期。所有形態ごとの合意形成と財源。

### 消耗品の交換・手入れをする

[PROCESS-010：消耗品の交換・手入れをする](routine-care.md)へ引き継ぐのは、軽微な手入れが必要と評価したときです。技術判断者が保守範囲か確認。工事が必要なら修繕案の具体化へ渡す。

[この業務の資料](#情報源)・[引継ぎ先の資料](routine-care.md#情報源)に基づく整理案。未確認：保守と修理工事の境界。機器別の作業資格・実施後の確認方法。

### 異常の連絡を受け、影響を判断する

[PROCESS-015：異常の連絡を受け、影響を判断する](incident-triage.md)へ引き継ぐのは、危険・異常の発見または再評価が必要なときです。管理者等が影響と緊急度を判断。切迫時は専門連絡・応急へ、非緊急は計画対応へ渡す。

[この業務の資料](#情報源)・[引継ぎ先の資料](incident-triage.md#情報源)に基づく整理案。未確認：苦情・改善要望と不具合の境界。緊急度基準・応答期限・担当引渡し条件。

### 修繕・交換の方法と範囲を決める

[PROCESS-017：修繕・交換の方法と範囲を決める](repair-design.md)へ引き継ぐのは、工事候補を技術的に具体化するときです。技術者と費用負担者等が性能・案・費用を検討。未決なら調査・計画調整を行う。

[この業務の資料](#情報源)・[引継ぎ先の資料](repair-design.md#情報源)に基づく整理案。未確認：設計・許認可の要否、代替案の比較基準。小修繕で省略できる成果の範囲。

### 台帳・図面・作業記録を更新し、引き継ぐ

[PROCESS-021：台帳・図面・作業記録を更新し、引き継ぐ](records-handover.md)へ引き継ぐのは、成果・判断・変更情報が発生または更新されたときです。記録管理者が対象・版・未完了事項を確認。欠落は不足として残す。

[この業務の資料](#情報源)・[引継ぎ先の資料](records-handover.md#情報源)に基づく整理案。未確認：保存年限・アクセス権・版管理。所有者変更時の図書引継ぎと欠落資料の扱い。

## 顧客の困りごとを確認する

以下は、この業務を理解するための質問です。顧客で確認済みの課題ではありません。

点検者・管理者に、次の点を聞きます。

指摘を出してから対応が決まるまで、どこで確認や判断が止まりますか。未点検箇所や対応待ちをどう区別していますか。

確認に使う情報：点検結果、指摘の引継ぎ、対応状況。記録の作成時間と、対応決定までの待ち時間を分ける。

## 未確認事項

- 消防・電気・昇降機等の法定条件と報告先。点検と詳しい劣化診断で異なる判断・成果。
