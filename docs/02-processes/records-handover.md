# 台帳・図面・作業記録を更新し、引き継ぐ

## 目的

設備の情報、図面、作業や判断の記録を残し、担当者が変わっても管理を続けられるようにします。

公開資料をもとにした業務の説明です。実際の担当や手順は、建物の条件・契約によって変わります。

<a id="対象業務領域"></a>

## この業務の分類

- 主領域：[DOMAIN-009：記録・報告・改善](../01-domains/records-evaluation.md)
- 関連領域：[DOMAIN-001：守るルール・利用条件](../01-domains/requirements.md)、[DOMAIN-002：作業・修繕・費用の計画](../01-domains/planning.md)、[DOMAIN-003：担当・発注・作業の調整](../01-domains/delivery-coordination.md)、[DOMAIN-004：日々の運転・手入れ・清掃](../01-domains/operations.md)、[DOMAIN-005：点検・測定](../01-domains/inspection-assessment.md)、[DOMAIN-006：異常・故障への対応](../01-domains/incident-response.md)、[DOMAIN-007：修繕・更新](../01-domains/repair-renewal.md)、[DOMAIN-008：事故の予防・災害への備え](../01-domains/risk-preparedness.md)

メニューでは「主領域」の分類から探せます。「関連領域」は、この業務と関わりのある分類です。

<a id="開始条件"></a>

## いつ始めるか

記録・図書の発生、設備・契約変更、担当交代、管理引継ぎ。

<a id="業務の性質適用条件"></a>

## 法令・契約・日常管理との関係

- 法令：保存義務の適用・年限は個別確認。
- 契約：成果物・引継条件。
- 運用：日常の情報継続。

一つの仕事に、法令・契約・日常管理の条件が重なることがあります。具体的な義務者・周期・資格・権限は建物・設備・契約の条件から確認する。

## 関係者・役割

担当者の例を示します。一人が複数の役割を持つ場合も、分担する場合もあります。責任や承認できる範囲は、法令・契約・建物の管理ルールで確認します。

| 担当者の例 | 役割 | 責任・判断 |
| --- | --- | --- |
| 各実施者 | 原記録の提供 | 原記録と変更情報の提供 |
| 情報管理担当者 | 記録管理 | 整理・更新 |
| 引継者・受領者 | 引継ぎ確認 | 不足と残課題の確認 |

<a id="入力"></a>

## 必要な情報

- 設備・建物情報
- 実施・点検・工事・判断記録
- 既存図書

## 標準フロー

概略のつながりのみを示す。発生した記録と対象・版を対応付けて更新し、判断・残課題・不足資料を引き継ぐ。

ここでは仕事の大まかな流れを示します。細かい手順や例外への対応は未確認です。

## 分岐・例外

現場で作る原記録の全てをこの業務だけに集めない。各業務の記録を関連付けて維持する。

<a id="出力"></a>

## 作業後に残すもの

- 更新された台帳・図書・履歴
- 版・対象の対応
- 引継事項・不足資料

<a id="外部起点と繰返し"></a>

## 外からの連絡・変更と繰り返し

- 外部からも開始する条件：記録・図書の発生、設備・契約変更、担当交代、管理引継ぎ。 前工程の完了だけが開始条件ではない。
- 変更・事象起点：対象の変更や新たな事象ごとに開始する。固定の実施周期を仮定しない。
- 全体との関係：[PROCESS-024：業務のつながり](lifecycle.md)。具体的な周期、緊急度、判断権限の未確定点は本書の未確認事項に従う。
