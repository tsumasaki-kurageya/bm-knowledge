# 修繕・交換工事を行い、仕上がりを確認する

## 目的

修繕・交換工事を行い、必要な機能や仕上がり、運転・管理に必要な情報を確認して引き渡します。

公開資料をもとにした業務の説明です。実際の担当や手順は、建物の条件・契約によって変わります。

<a id="対象業務領域"></a>

## この業務の分類

- 主領域：[DOMAIN-007：修繕・更新](../01-domains/repair-renewal.md)
- 関連領域：[DOMAIN-003：担当・発注・作業の調整](../01-domains/delivery-coordination.md)、[DOMAIN-004：日々の運転・手入れ・清掃](../01-domains/operations.md)、[DOMAIN-005：点検・測定](../01-domains/inspection-assessment.md)、[DOMAIN-006：異常・故障への対応](../01-domains/incident-response.md)

メニューでは「主領域」の分類から探せます。「関連領域」は、この業務と関わりのある分類です。

<a id="開始条件"></a>

## いつ始めるか

工事案・依頼条件と実施条件が整ったとき、応急後の修理手配。

<a id="業務の性質適用条件"></a>

## 法令・契約・日常管理との関係

- 法令：工事・設備ごとの要件を確認。
- 契約：施工・試験・成果物の条件。
- 運用：引渡し後の設定・保守へ接続。

一つの仕事に、法令・契約・日常管理の条件が重なることがあります。具体的な義務者・周期・資格・権限は建物・設備・契約の条件から確認する。

## 関係者・役割

担当者の例を示します。一人が複数の役割を持つ場合も、分担する場合もあります。責任や承認できる範囲は、法令・契約・建物の管理ルールで確認します。

| 担当者の例 | 役割 | 責任・判断 |
| --- | --- | --- |
| 施工者・メーカー | 施工・情報提供 | 施工と機器情報の提供 |
| 技術確認者・監理者等 | 技術的確認 | 要求性能の確認 |
| 管理者・運用担当者 | 引渡し情報の受領 | 運用情報の受領 |

<a id="入力"></a>

## 必要な情報

- 工事・設計条件
- 契約・作業条件
- 現況図書
- 確認項目

## 標準フロー

概略のつながりのみを示す。合意した条件に基づき工事を実施し、必要な技術的確認を行って、設備・図書・残課題を引き渡す。

ここでは仕事の大まかな流れを示します。細かい手順や例外への対応は未確認です。

## 分岐・例外

技術的な引渡しを扱う。契約履行の受領判断は別業務に関係付ける。

## 作業後に残すもの

- 施工・試験等の結果
- 変更図書・運用条件
- 未完了・残課題

## 外からの連絡・変更と繰り返し

- 外部からも開始する条件：工事案・依頼条件と実施条件が整ったとき、応急後の修理手配。 前工程の完了だけが開始条件ではない。
- 変更・事象起点：対象の変更や新たな事象ごとに開始する。固定の実施周期を仮定しない。
- 全体との関係：[PROCESS-024：業務のつながり](lifecycle.md)。具体的な周期、緊急度、判断権限の未確定点は本書の未確認事項に従う。
