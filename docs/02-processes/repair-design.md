# 修繕・交換の方法と範囲を決める

## 目的

どこを、どの方法で直す・交換するかを具体化し、工事を行うか判断できるようにします。

公開資料をもとにした業務の説明です。実際の担当や手順は、建物の条件・契約によって変わります。

<a id="対象業務領域"></a>

## この業務の分類

- 主領域：[DOMAIN-007：修繕・更新](../01-domains/repair-renewal.md)
- 関連領域：[DOMAIN-002：作業・修繕・費用の計画](../01-domains/planning.md)、[DOMAIN-003：担当・発注・作業の調整](../01-domains/delivery-coordination.md)

メニューでは「主領域」の分類から探せます。「関連領域」は、この業務と関わりのある分類です。

<a id="開始条件"></a>

## いつ始めるか

計画対象の具体化、点検指摘、応急対応後の恒久対策。

<a id="業務の性質適用条件"></a>

## 法令・契約・日常管理との関係

- 法令：工事内容に応じた要件を確認。
- 契約：設計・調査委託等の範囲。
- 運用：既存建物を使用しながら行う条件。

一つの仕事に、法令・契約・日常管理の条件が重なることがあります。具体的な義務者・周期・資格・権限は建物・設備・契約の条件から確認する。

## 関係者・役割

担当者の例を示します。一人が複数の役割を持つ場合も、分担する場合もあります。責任や承認できる範囲は、法令・契約・建物の管理ルールで確認します。

| 担当者の例 | 役割 | 責任・判断 |
| --- | --- | --- |
| 設計者・専門家 | 技術案の具体化 | 技術案の具体化 |
| 管理者・利用者 | 利用条件の調整 | 利用条件の調整 |
| 所有者・費用負担者 | 対策・予算の判断 | 案と予算の判断 |

<a id="入力"></a>

## 必要な情報

- 状態評価
- 要求・利用条件
- 計画・予算
- 技術案・概算

## 標準フロー

概略のつながりのみを示す。状態と要求から対策案を比較し、必要な調査・設計等で範囲を具体化して、実施条件と費用を判断に渡す。

ここでは仕事の大まかな流れを示します。細かい手順や例外への対応は未確認です。

## 分岐・例外

中長期計画の概算と、実行する工事案の具体化を区別する。

<a id="出力"></a>

## 作業後に残すもの

- 選定する対策案・範囲
- 設計等の実施条件
- 費用・停止影響
- 計画修正事項

## 外からの連絡・変更と繰り返し

- 外部からも開始する条件：計画対象の具体化、点検指摘、応急対応後の恒久対策。 前工程の完了だけが開始条件ではない。
- 変更・事象起点：対象の変更や新たな事象ごとに開始する。固定の実施周期を仮定しない。
- 全体との関係：[PROCESS-024：業務のつながり](lifecycle.md)。具体的な周期、緊急度、判断権限の未確定点は本書の未確認事項に従う。
