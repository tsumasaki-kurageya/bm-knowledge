# 適用要求・利用条件の整理

## 目的

適用漏れと要求の取り違えを防ぎ、計画・実施の前提を共有する。

[PROCESS-001：業務カタログ](overview.md)に属する概略文書。目的・入出力・役割・前後関係は、記載した情報源の構成要素を本知識ベースで業務単位にまとめた整理案であり、現場で確認した実態や一律の法定手順ではない。

## 対象業務領域

- 主領域：[DOMAIN-001：要求・適用条件の管理](../01-domains/requirements.md)
- 関連領域：[DOMAIN-002：保全計画・資金計画](../01-domains/planning.md)、[DOMAIN-003：業務実施体制・発注調整](../01-domains/delivery-coordination.md)

主領域は主な成果の置き場所。関連領域ごとに別のProcessを重複作成しない。

## 開始条件

管理開始、用途・設備・契約・利用要求の変更、要求の定期見直し。

## 業務の性質・適用条件

- 法令：適用判定の対象。
- 契約：合意事項を法的義務と区別。
- 運用：任意の利用目標も別に記録。

「法令・契約・運用」は排他的ではない。具体的な義務者・周期・資格・権限は建物・設備・契約の条件から確認する。

## 関係者・役割

主体は役割の例。同じ主体の兼務や複数主体での分担があり、最終的な責任・決裁権限は法令・契約・管理条件で確認する。

| 主体 | 役割 | 責任・判断 |
| --- | --- | --- |
| 管理者・専門家 | 要求整理・適用確認 | 条件の収集と適用確認 |
| 所有者・権原者 | 方針判断 | 要求・責任の確認と方針判断 |
| 利用者 | 利用条件の提示 | 利用条件の提示 |

## 入力

- 建物・設備概要
- 所有・管理権原
- 法令・条例・契約の候補
- 利用要求

## 標準フロー

概略のつながりのみを示す。建物・契約・利用の条件を整理し、適用根拠と確認できない条件を分けて、要求を関係者へ共有する。

詳細な手順・分岐・例外は後続Issueで整理する。

## 分岐・例外

将来の工事内容・予算の決定は計画へ渡す。全用途の法定業務を一律に決めない。

## 出力

- 適用根拠・対象・義務者を区別した要求一覧
- 確認できない条件・照会先
- 変更事項

## 外部起点と繰返し

- 外部からも開始する条件：管理開始、用途・設備・契約・利用要求の変更、要求の定期見直し。 前工程の完了だけが開始条件ではない。
- 変更・事象起点：対象の変更や新たな事象ごとに開始する。固定の実施周期を仮定しない。
- 全体との関係：[PROCESS-024：業務関係とライフサイクル](lifecycle.md)。具体的な周期、緊急度、判断権限の未確定点は本書の未確認事項に従う。
