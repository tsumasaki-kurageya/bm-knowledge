# 作業の結果を振り返り、計画を見直す

## 目的

作業によって必要な状態を保てたか、まだ問題が残っていないかを振り返り、次の計画に反映します。

公開資料をもとにした業務の説明です。実際の担当や手順は、建物の条件・契約によって変わります。

<a id="対象業務領域"></a>

## この業務の分類

- 主領域：[DOMAIN-009：記録・報告・改善](../01-domains/records-evaluation.md)
- 関連領域：[DOMAIN-001：守るルール・利用条件](../01-domains/requirements.md)、[DOMAIN-002：作業・修繕・費用の計画](../01-domains/planning.md)、[DOMAIN-003：担当・発注・作業の調整](../01-domains/delivery-coordination.md)

メニューでは「主領域」の分類から探せます。「関連領域」は、この業務と関わりのある分類です。

<a id="開始条件"></a>

## いつ始めるか

定期的な振返り、重要事象、計画見直し、管理条件の変更。

<a id="業務の性質適用条件"></a>

## 法令・契約・日常管理との関係

- 法令：履行状況を評価材料にする。
- 契約：合意した報告・評価条件。
- 運用：管理の継続的な振返り。

一つの仕事に、法令・契約・日常管理の条件が重なることがあります。具体的な義務者・周期・資格・権限は建物・設備・契約の条件から確認する。

## 関係者・役割

担当者の例を示します。一人が複数の役割を持つ場合も、分担する場合もあります。責任や承認できる範囲は、法令・契約・建物の管理ルールで確認します。

| 担当者の例 | 役割 | 責任・判断 |
| --- | --- | --- |
| 管理者・評価担当者 | 実績評価 | 実績の整理・評価 |
| 所有者・権限者 | 方針変更の判断 | 方針変更の判断 |
| 実施者・利用者 | 結果・影響の共有 | 結果・影響の共有 |

<a id="入力"></a>

## 必要な情報

- 要求・目標
- 状態と実施実績
- 費用・未対応事項
- 利用者からの情報

## 標準フロー

概略のつながりのみを示す。状態・実施・費用等を要求に照らして評価し、判断が必要な論点を整理して、次の要求・計画・体制へ返す。

ここでは仕事の大まかな流れを示します。細かい手順や例外への対応は未確認です。

## 分岐・例外

個々の設備状態の判定と全体評価を分ける。本書は業務の存在を整理し、特定現場の課題・改善案を評価しない。

<a id="出力"></a>

## 作業後に残すもの

- 実績評価
- 見直す要求・計画・体制の論点
- 判断根拠と残る確認事項

<a id="外部起点と繰返し"></a>

## 外からの連絡・変更と繰り返し

- 外部からも開始する条件：定期的な振返り、重要事象、計画見直し、管理条件の変更。 前工程の完了だけが開始条件ではない。
- 繰返し：次の合意済み実施時期・評価時期等で本業務を再開する。毎回同じ計画・発注・承認をやり直すとは限らず、条件変更がある場合に見直す。周期・期限は法令・契約・管理計画で確認する。
- 全体との関係：[PROCESS-024：業務のつながり](lifecycle.md)。具体的な周期、緊急度、判断権限の未確定点は本書の未確認事項に従う。
