# 設備を運転・監視し、設定を調整する

## 目的

建物の使い方に合わせて設備を動かし、運転状況を見ながら設定を調整します。

公開資料をもとにした業務の説明です。実際の担当や手順は、建物の条件・契約によって変わります。

<a id="対象業務領域"></a>

## この業務の分類

- 主領域：[DOMAIN-004：日々の運転・手入れ・清掃](../01-domains/operations.md)
- 関連領域：[DOMAIN-005：点検・測定](../01-domains/inspection-assessment.md)

メニューでは「主領域」の分類から探せます。「関連領域」は、この業務と関わりのある分類です。

<a id="開始条件"></a>

## いつ始めるか

運転時刻、利用条件変更、監視値の変化、修繕後の引渡し。

<a id="業務の性質適用条件"></a>

## 法令・契約・日常管理との関係

- 法令：設備・環境の適用要求に従う。
- 契約：運転時間・範囲等。
- 運用：日々の利用条件への対応。

一つの仕事に、法令・契約・日常管理の条件が重なることがあります。具体的な義務者・周期・資格・権限は建物・設備・契約の条件から確認する。

## 関係者・役割

担当者の例を示します。一人が複数の役割を持つ場合も、分担する場合もあります。責任や承認できる範囲は、法令・契約・建物の管理ルールで確認します。

| 担当者の例 | 役割 | 責任・判断 |
| --- | --- | --- |
| 運転担当者 | 運転・監視 | 権限内の運転・監視 |
| 管理者・施設運営者 | 運用条件の判断 | 運用条件の判断 |
| 利用者・専門家 | 利用・技術条件の提示 | 要望・技術条件の提示 |

<a id="入力"></a>

## 必要な情報

- 設備・制御情報
- 運転条件
- 状態・警報
- 利用予定

## 標準フロー

概略のつながりのみを示す。利用・設備条件に従って運転を行い、状態に応じて設定を調整し、異常と変更情報を引き継ぐ。

ここでは仕事の大まかな流れを示します。細かい手順や例外への対応は未確認です。

## 分岐・例外

運転のための監視が中心。独立した状態判定は点検・測定へ渡す。

<a id="出力"></a>

## 作業後に残すもの

- 運転・設定変更の結果
- 監視記録
- 異常の連絡事項

<a id="外部起点と繰返し"></a>

## 外からの連絡・変更と繰り返し

- 外部からも開始する条件：運転時刻、利用条件変更、監視値の変化、修繕後の引渡し。 前工程の完了だけが開始条件ではない。
- 繰返し：次の合意済み実施時期・評価時期等で本業務を再開する。毎回同じ計画・発注・承認をやり直すとは限らず、条件変更がある場合に見直す。周期・期限は法令・契約・管理計画で確認する。
- 全体との関係：[PROCESS-024：業務のつながり](lifecycle.md)。具体的な周期、緊急度、判断権限の未確定点は本書の未確認事項に従う。
