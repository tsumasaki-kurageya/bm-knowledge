# 業務の分類

建物の維持保全に必要な仕事を、目的に応じて9つに分けています。各分類のページから、具体的な仕事の手順へ進めます。

公開資料をもとにしたこのガイド独自の分類です。法令で定められた分類ではありません。建物ごとに必要な仕事・周期・資格は、個別に確認します。

## 9つの業務分類

各分類が、[建物維持保全の全体像（BUSINESS-001）](../00-business/overview.md)で説明する目的にどう役立つかを示します。一つの仕事が複数の目的を支えることもあります。

| 領域 | 成立させること・主な範囲 | 主に支える目的 |
| --- | --- | --- |
| [DOMAIN-001：守るルール・利用条件](requirements.md) | 適用条件と求められる状態を明らかにする | 法令等への適合、管理の継続性 |
| [DOMAIN-002：作業・修繕・費用の計画](planning.md) | 対策・時期・優先度・資金を見通す | 資産保全、経済性・実行可能性 |
| [DOMAIN-003：担当・発注・作業の調整](delivery-coordination.md) | 役割・資源・依頼条件と契約どおりの作業かの確認を整える | 経済性・実行可能性、管理の継続性 |
| [DOMAIN-004：日々の運転・手入れ・清掃](operations.md) | 運転・手入れ・清掃等で状態を保つ | 衛生・利用環境、機能継続、資産保全 |
| [DOMAIN-005：点検・測定](inspection-assessment.md) | 状態と要求との差、対応要否を把握する | 人の安全、衛生・利用環境、機能継続、法令等への適合、資産保全 |
| [DOMAIN-006：異常・故障への対応](incident-response.md) | 異常の影響を抑え、復旧へつなぐ | 人の安全、機能継続 |
| [DOMAIN-007：修繕・更新](repair-renewal.md) | 必要な性能を回復・確保して引き渡す | 資産保全、機能継続、人の安全 |
| [DOMAIN-008：事故の予防・災害への備え](risk-preparedness.md) | 危険を予防し、非常時に対応できる条件を保つ | 人の安全、機能継続 |
| [DOMAIN-009：記録・報告・改善](records-evaluation.md) | 情報を引き継ぎ、保全全体の結果を見直しへ返す | 管理の継続性、法令等への適合。評価では7目的全体を扱う |

## 主要業務への入口

[PROCESS-001：業務フロー一覧](../02-processes/overview.md)で22の仕事を探せます。各分類ページの「個別の業務フロー」からも、必要な情報や前後の仕事をたどれます。対象別の詳細手順や法令適用は引き続き確認する。

## 領域間のつながり

次図は、状態に対処する領域間の主な循環を示す。記載のない直接の受渡しもあり、詳細手順や固定的な承認経路ではない。図の名称はメニューの分類に対応します。

```mermaid
flowchart TD
  D4["DOMAIN-004 日々の運転・手入れ・清掃"]
  D5["DOMAIN-005 点検・測定"]
  D6["DOMAIN-006 異常・故障への対応"]
  D7["DOMAIN-007 修繕・更新"]
  D8["DOMAIN-008 事故の予防・災害への備え"]
  D4 -->|状態情報| D5
  D5 -->|調整・手入れ| D4
  D4 -->|異常の検知| D6
  D5 -->|危険・障害| D6
  D5 -->|対策候補| D7
  D6 -->|恒久対策| D7
  D7 -->|引渡し| D4
  D8 -->|事前の対応条件| D6
  D6 -->|備えの見直し| D8
```

要求・計画・実施体制・記録評価は、図の活動を横断して支える。これらは現場作業の前後に一度だけ行うものではない。

| 支える領域 | 主な受渡しと戻り |
| --- | --- |
| [DOMAIN-001：守るルール・利用条件](requirements.md) | 建物・利用条件から要求を整理し、計画・実施体制へ渡す。履行状況や変更から要求を見直す |
| [DOMAIN-002：作業・修繕・費用の計画](planning.md) | 状態評価と全体評価から対策・時期・予算を決める。実施結果や工事具体化による変更を取り込む |
| [DOMAIN-003：担当・発注・作業の調整](delivery-coordination.md) | 各実施領域に役割・資源・依頼条件を整え、実施結果を確認する。制約は計画へ戻す |
| [DOMAIN-009：記録・報告・改善](records-evaluation.md) | 全領域の状態・実績・判断を引き継ぎ、要求・計画・体制・予防の見直しへ返す |

例えば点検指摘は緊急度により異常対応または修繕計画へつながり、修繕後は運用条件と図書が更新される。緊急時に全ての計画手順を先行させる意味ではない。活動の時間軸は[日々の仕事と将来の計画（BUSINESS-003）](../00-business/value-stream.md)も参照。

## 対象別の分類との対応

普段使う「設備管理」「清掃」「警備」などの仕事の呼び方からも探せます。設備などの対象名と作業名が混ざっていますが、知っている仕事と9分類をつなぐための入口です。表の業務例は機能分類への**当てはめ例**で、網羅的な仕様・法定一覧ではない。

| 対象・慣用的な作業群 | 主に関係する機能と例 |
| --- | --- |
| 建築・敷地 | [DOMAIN-005：点検・測定](inspection-assessment.md)：外壁等の状態確認、[DOMAIN-007：修繕・更新](repair-renewal.md)：補修、[DOMAIN-004：日々の運転・手入れ・清掃](operations.md)：手入れ |
| 電気・空調・給排水等の設備 | [DOMAIN-004：日々の運転・手入れ・清掃](operations.md)：運転、[DOMAIN-005：点検・測定](inspection-assessment.md)：機能確認、[DOMAIN-006：異常・故障への対応](incident-response.md)：故障対応、[DOMAIN-007：修繕・更新](repair-renewal.md)：更新 |
| 清掃 | [DOMAIN-004：日々の運転・手入れ・清掃](operations.md)：清掃作業、[DOMAIN-005：点検・測定](inspection-assessment.md)：仕上がり・状態の確認、[DOMAIN-003：担当・発注・作業の調整](delivery-coordination.md)：作業条件の調整 |
| 環境衛生 | [DOMAIN-001：守るルール・利用条件](requirements.md)：適用条件、[DOMAIN-005：点検・測定](inspection-assessment.md)：空気・水等の測定、[DOMAIN-004：日々の運転・手入れ・清掃](operations.md)：調整・防除、[DOMAIN-007：修繕・更新](repair-renewal.md)：設備対策 |
| 警備・防犯 | [DOMAIN-008：事故の予防・災害への備え](risk-preparedness.md)：警戒・入退管理、[DOMAIN-006：異常・故障への対応](incident-response.md)：発生事象への対応、[DOMAIN-003：担当・発注・作業の調整](delivery-coordination.md)：権限・依頼条件 |
| 防火・防災 | [DOMAIN-008：事故の予防・災害への備え](risk-preparedness.md)：備え・訓練、[DOMAIN-005：点検・測定](inspection-assessment.md)：関連設備の点検、[DOMAIN-007：修繕・更新](repair-renewal.md)：修繕、[DOMAIN-006：異常・故障への対応](incident-response.md)：非常時の対応 |

いずれの対象にも計画・実施体制・記録評価が関係する。対象設備がない建物には該当作業がなく、必要な行為と担当は用途・規模・権原・設備・契約によって変わる。

## 分類で迷いやすい仕事

- **周期と機能を分ける。** 日常点検はDOMAIN-005、定期清掃はDOMAIN-004。中長期計画はDOMAIN-002が扱い、結果を短期の運用・工事へ反映する。日常業務と長期業務は別々の体系にしない。
- **法定性と機能を分ける。** 適用要求の整理はDOMAIN-001、法定点検の実施はDOMAIN-005、結果の提出・追跡はDOMAIN-009に関係付ける。「法令対応」に全作業を集めない。
- **運転監視・点検・警戒を目的で見分ける。** 運転を調整するための監視はDOMAIN-004、状態判定はDOMAIN-005、危険発生の予防はDOMAIN-008。同じ巡回が複数にまたがることを許容する。
- **保守・応急措置・修繕を固定金額で分けない。** 日常の軽微な手入れはDOMAIN-004、被害を抑えて復旧へつなぐ判断はDOMAIN-006、工事や更新の具体化・実施はDOMAIN-007。原典の用語と契約上の作業範囲も併記する。
- **設備状態と全体評価を分ける。** DOMAIN-005は対象の状態を判定し、DOMAIN-009は要求に対する保全全体の結果や残課題を扱う。

## 未確認事項

- 官庁施設・マンション向け資料の比重が大きく、民間非住宅、自営、複数所有等の現場への当てはまりは未検証です。
- 病院・工場・宿泊施設等の用途固有の要求、省エネルギー・廃棄物等の扱いは、各分野の原典で確認が必要です。
- 建物ごとの法令・規格の適用は未確定です。法的義務をすべて列挙したものや、ISO規格への適合を示したものではありません。
- 計画・担当調整・警備・防災の具体的な役割分担は、契約と現場の記録で確認します。
