# Evidence の情報管理・匿名化方針

現場訪問、ヒアリング、問い合わせ、文書から Evidence を保存するときに適用します。

## 基本方針

- 業務分析に必要な情報だけを記録する。
- 生の Evidence と、一般化した知識・解釈を分離する。
- 顧客、物件、個人を特定できる情報は必要最小限にする。
- リポジトリへ保存してよいか判断できない情報は保存しない。

## 記録しない情報

- 氏名、メールアドレス、電話番号など、分析に不要な個人情報
- ID、パスワード、API キー、アクセストークン、接続文字列などの認証情報
- 契約で保存・共有を制限された情報
- 顧客の許可なく転載できない図面、写真、帳票、録音、全文記録
- 匿名化しても他の情報との組み合わせで容易に再特定できる情報

## 匿名化

- 顧客名、会社名、物件名、個人名は、分析上区別が必要な場合だけ一貫した仮名へ置き換える。
- 正確な住所、日時、金額、設備番号などが不要な場合は、地域、月、金額帯、設備種別などへ粒度を下げる。
- 仮名と実名の対応表はこのリポジトリに保存しない。
- 匿名化によって意味が変わる場合は、詳細を伏せた理由と分析上の制約を記載する。

## 事実と解釈

Evidence には次を別の見出しで記載します。

- **観察事項・発言・問い合わせ内容**: 実際に確認した内容。要約した場合はその旨を示す。
- **解釈**: 観察から考えられる意味、標準業務との差分、仮説。

解釈を確定事項として扱いません。複数事例から一般化する場合も、根拠となる Evidence ID と適用範囲を示します。

## 情報源の記録

再確認に必要な範囲で、情報源種別、取得日、対象、資料名、発行主体、URL、参照日を記録します。非公開情報については、アクセス権限や転載可否を確認し、リンクや所在だけを記録する方法も検討します。

## 保存前チェック

- 分析に不要な個人情報・固有名詞を削除したか
- 認証情報や秘密情報が含まれていないか
- 保存・共有・転載の権限があるか
- 事実と解釈を分けたか
- 関連する Domain / Process の ID を記載したか
- 保存可否に迷う情報を除外したか
