# Evidence の登録と初期投入

現場訪問・発言・問い合わせ・帳票等の確認可能な記録を、標準業務と分離して蓄積するための運用案内。これは個別のEvidenceではないため、Evidence IDは付与しない。

[情報管理・匿名化方針](information-management.md)、[記録テンプレート](../../templates/evidence.md)、[Frontmatter・ID規約](../../schemas/frontmatter.md)を使用する。

## 初期投入の状態

2026-09-14時点で、リポジトリ内に初期投入できる実際の現場記録は未登録。Issue #7は**実データ待ちで未完了**。テンプレートや本案内の整備だけでは「少数件、実データで登録して運用を検証」の完了条件を満たさない。

初期投入は1〜3件を目安とし、内容を確認できる記録から始める。これは運用上の目安であり、件数だけで検証完了と判断しない。架空例や公的仕様書を、特定現場の運用を示す実データの代わりに投入しない。

## 最初に用意する情報

登録用の資料は、原文全体である必要はない。保存できる範囲の匿名化した要点でも、何を確認した記録かと再確認の方法が分かれば扱える。

| 情報 | 記載する内容 |
| --- | --- |
| 種別・日付 | 訪問／発言／問い合わせ等の区別。事象の日付と取得日を混同しない。不明は不明とする |
| 対象・役割 | 必要な範囲の匿名化した対象、発言者・作業者の役割。実名との対応表は保存しない |
| 確認した内容 | 誰が何をした／述べたか、使用情報、前後の仕事。見ていない部分を推定しない |
| 元記録への戻り方 | 保存可能な資料名・該当箇所・所在。元資料を確認できなければ制約を記録 |
| 保存できる範囲 | 要点・原文・画像等のどこまで保存可能か。判断できない内容は登録しない |

過去の会話の記憶や要約だけでは、正確な発言・観察の確認に不足する場合がある。顧客の運用と無関係な技術相談を、建物維持保全の実態として付け替えない。

## 保存先と単位

| 主な情報源 | 保存先 |
| --- | --- |
| 現場訪問の観察 | `site-visits/` |
| ヒアリング・発言 | `interviews/` |
| 問い合わせ・運用上の質問や要望 | `support-tickets/` |
| 実際の帳票・手順等を確認した記録 | `documents/` |

一つの確認可能な事象・発言・問い合わせを基本単位にする。同じ元記録を複数のフォルダに重複登録せず、複数Domain / Processへ関連付ける。長い記録を分割する場合は、元記録・該当箇所と各Evidenceの関係を残す。

## 登録手順

1. 情報管理方針に沿い、保存する範囲と匿名化を確認する。不要な固有名詞・識別情報・認証情報を除く。
2. 既存のEvidence・ID・元記録を検索し、重複がないか確認する。未登録の実記録にだけIDを採番する。現在は実Evidence未登録のため最初はEVIDENCE-001だが、登録時に必ず再検索する。
3. テンプレートを該当フォルダへ複製する。事実・発言、標準との差の候補、解釈、未確認事項を分けて記入する。
4. 関連するDomain / ProcessのID・リンクと理由を記載する。対応が不明なら推定で確定せず、照合候補と未確認事項を残す。
5. 関連付けを確認できたDomain / Processに「関連する現場Evidence」を追加し、Evidence ID・相対リンク・確認内容・適用範囲を簡潔に記載する。標準フロー自体は書き換えない。
6. このページの「登録済みEvidence」に同じID・リンクを追加し、双方向の参照、事実と解釈、保存範囲をレビューする。
7. 記録時に不足した項目・粒度・匿名化・リンクの問題を残し、実データで試した結果をPRに記載する。テンプレートを変更した場合は理由を残す。

statusは文書の整理状況、confidenceは内容の確からしさを表す。実データであっても伝聞・範囲不明等の制約は別に残し、「実データだからverified」としない。

## 標準業務への関連付け

| 観察・記録の焦点 | 初期の照合候補 | 比較時の注意 |
| --- | --- | --- |
| 作業日程・停止・入室・立会いの調整 | [PROCESS-007](../02-processes/work-coordination.md)、[DOMAIN-003](../01-domains/delivery-coordination.md) | 権限・契約条件と、実際に誰が調整したかを分ける |
| 点検・記入・状態判定・異常の連絡 | [PROCESS-013](../02-processes/inspection.md)、[DOMAIN-005](../01-domains/inspection-assessment.md) | 点検種別・対象範囲が違えば、直ちに標準との差とはいえない |
| 実施報告・確認・差戻し | [PROCESS-008](../02-processes/completion-check.md)、[DOMAIN-003](../01-domains/delivery-coordination.md) | 作業完了・履行確認・支払を混同しない |
| その他の業務 | [PROCESS-001：業務カタログ](../02-processes/overview.md)、[DOMAIN-000：業務領域一覧](../01-domains/overview.md) | 実際の内容から照合し、無理に上記3件へ寄せない |

PROCESS-007・013・008の詳細化は官庁施設向け委託仕様を標準例としている。別の用途・制度・契約による差を、そのまま不備・違反・改善機会と認定しない。

Evidenceは標準の適用を証明するものでもない。リンクには「関連する実態」と分かる見出しを使い、標準の情報源と混ぜない。

## 登録済みEvidence

未登録。実データを登録した際に、ID・リンク・情報源種別・事象の時期・関連Domain / Process・確認上の制約をここへ記載する。仮のEvidence行・架空の登録件数は作らない。

## 初期投入で確認する事項

- [ ] 少数の実Evidenceを登録し、再確認できる情報源・範囲を残した
- [ ] EvidenceからDomain / Processへ辿れる
- [ ] 標準業務側からEvidenceへ辿れる
- [ ] 観察・発言・要望と解釈を区別した
- [ ] 匿名化・保存範囲を確認した
- [ ] 不足した項目・運用上の問題、または今回の試行で問題がなかった範囲を記録した

現時点では実投入前のため、これらは未検証。試行後に結果と対象Evidenceを追記する。後続の一般化・差分分析はInsightで行う。
